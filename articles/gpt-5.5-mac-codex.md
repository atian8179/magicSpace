过去 AI 是个能聊天的窗口。

## Codex 是什么？一句话讲清

**Codex 是 OpenAI 做的 AI 编程代理。**

但这句话很容易把它讲小。

因为今天的 Codex 不只是"写代码"，它有好几个入口：

- **Codex App**：一个 AI 工作台，可以开多个任务、多个项目、多个 agent
- **Codex CLI**：跑在你的终端里，能读文件、改文件、跑命令
- **浏览器扩展**：让 Codex 借用你已经登录的网页状态去操作
- **Computer Use**：像人一样操作 Mac 上的应用窗口
- **Connectors / 技能**：装上专用能力，比如 GitHub、Figma、Canva、Google Drive、Slack、图片生成、PPT、表格、文档
- **Automations**：定时跑任务，每天整理邮箱、每周生成周报、定期检查表格

## Mac 用户，这次真的别再观望了

不是 Windows 不能用 Codex。

Codex CLI 本身就支持 macOS、Windows、Linux。

我说 Mac，是因为 Mac 用户最容易感受到这套体验的完整形态：

- 本地终端稳定
- 开发环境集中
- 浏览器登录态完整
- App 权限体系清晰
- 文件、图片、文档、代码都在同一台机器上
- Computer Use 可以直接跨窗口操作

更直白一点：**AI 时代，Mac 生态确实有先发优势。**

不是玄学，是产品上的事实。

Codex 桌面版、各种本地 agent、截图 / OCR、菜单栏助手、全局快捷键、系统级权限、浏览器自动化、文件夹访问、App 间跳转——Mac 上的体验往往更早、更完整，也更丝滑。

原因也很现实：大量 AI 开发者自己就在 Mac 上工作。产品第一版当然先解决自己每天遇到的问题。

所以你会明显感觉到：

**同样一个 AI 功能，Mac 用户先用上，Windows 用户等一等。**

这个差距不是永久的，但在产品早期非常明显。

## 案例 1：一句话装个 Agent，从 README 到跑通

第一个案例最适合打开认知。

你可以让 Codex 帮你安装另一个 Agent。

比如曾经很火的 OpenClaw，或者最近讨论度很高的 Hermes Agent。

你不需要自己翻 README，不需要判断该用 npm、pipx、curl 还是 Docker，也不需要手动排环境变量。

直接说：

```
帮我在这台 Mac 上安装 Hermes Agent。
1. 先查官方 GitHub README 和安装文档；
2. 告诉我它会执行哪些命令；
3. 不要直接运行 curl 脚本，先让我确认；
4. 安装后跑一遍自检；
5. 最后把安装路径、配置文件、卸载方式整理给我。
```

Codex 会做什么？

它会去看官方仓库，识别系统环境，检查依赖，给出安装路径，执行命令，修 PATH，跑诊断，然后告诉你下一步怎么启动。

如果你要装 OpenClaw 一类的技能库，可以再加一句安全检查：

```
帮我装 OpenClaw 相关技能，但先做安全审查。
列出每个技能会访问什么权限、写入哪些目录、是否执行外部脚本。
高风险的先别装，先解释给我听。
```

重点不是"它会执行命令"。

**重点是：它会先读资料、判断环境、规划步骤、等你批准，然后才动手。**

**图9：Codex 安装 Hermes / OpenClaw 的终端截图**

配图建议：用真实安装过程截图最有说服力。左侧是 Codex 对话，右侧是终端安装日志，下方做三个结果卡片：安装成功 / 自检通过 / 卸载方式已记录。

不过这里得说一句重话——

**给 Agent 完全访问权限，不等于可以闭眼乱装。**

OpenClaw、Hermes 这类工具本来就会接触终端、文件、网络、消息平台。它们越强，权限风险越高。

正确姿势不是：

> "帮我装，随便执行。"

而是：

> "先审脚本、列权限、解释风险、等我确认。"

**真正的 AI 协作姿势，不是把所有权限都打开，而是知道什么时候该放权、什么时候该踩刹车。**

## 案例 2：一句话清理电脑，再也不用翻文件夹

Mac 越用越卡，很多时候不是机器不行，是垃圾堆满了。

以前清理磁盘，你要自己翻：

- Downloads
- 桌面
- Xcode DerivedData
- node_modules
- Docker 镜像
- 浏览器缓存
- iPhone 备份
- 大视频文件
- 重复压缩包

翻到一半，人已经烦了。

现在可以直接把这件事丢给 Codex：

```
帮我分析这台 Mac 的磁盘占用。
1. 只分析，不删除；
2. 按"安全可删 / 需要确认 / 不建议碰"分组；
3. 列出预计可释放空间；
4. 给我 3 个清理方案：保守、标准、激进；
5. 等我选择后，再执行清理。
```

Codex 会先扫盘，找出大文件和大目录。

然后告诉你：

- 哪些是缓存，可以删
- 哪些是构建产物，可以重建
- 哪些是 Docker 镜像，可以 prune
- 哪些是下载文件，需要你确认
- 哪些是照片、邮件、系统文件，不应该动

你选"标准清理"之后，它再执行。

清完还会复盘：

> 本次释放 38.6GB，其中 Xcode DerivedData 12.1GB、Docker 18.4GB、Downloads 压缩包 8.1GB。

这比任何"清理大师"都舒服。

因为它不是一个固定脚本——**它知道你电脑上到底发生了什么。**

**图10：磁盘清理前后对比**

配图建议：做一张 before / after 数据卡片。左边红色：剩余 18GB，右边绿色：释放 42GB。中间是 Codex 给出的三档清理方案。

清理这类任务，一定要加一句：

> **"先列方案，不要直接删除。"**

未来你和 AI 协作，最核心的能力不是写复杂 prompt，而是**会设置边界**。

## 案例 3：让 Mac 自己帮你填表申请

这个场景特别像未来。

不是写代码，就是让 AI 操作你的电脑。

比如你要申请一份开发者激励（小米百万 tokens 也好，OpenAI 的开发者补贴也好），要打开页面、登录账号、填写申请理由、补项目介绍、检查格式。

以前这类事你会拖。

因为它不难，但很碎。

现在你可以说：

```
打开这个申请页面，根据我下面的项目背景填表。
1. 不要提交，提交前停下来让我确认；
2. 申请理由要真诚，别像 AI 套话；
3. 项目介绍控制在 300 字内；
4. 如果页面需要登录或验证码，提醒我手动处理；
5. 填完后逐项检查有没有遗漏。

项目背景：
我是一个独立开发者，做 AI 编程教育和工具产品……
```

Codex 会用你已经登录的浏览器进入页面，扫一遍表单字段，判断哪些该填、哪些该留空、哪里需要你确认。

最爽的是，它不是只帮你"写一段申请理由"。

**它是把申请这件事跑完——写理由只是其中一步。**

**图11：Codex 操作浏览器填写表单**

配图建议：浏览器表单界面 + 右侧 Codex 任务列表。表单字段里显示"项目简介 / 申请理由 / 使用计划"，底部按钮"提交前等待确认"高亮。

这里也得提醒：

**凡是涉及提交、付款、发消息、删文件、授权的动作，都让 Codex 在最后一步停下。**

AI 可以帮你省掉大半的重复劳动。

但最后一公里的责任，还是你来扛。

## 案例 5：一个人，一晚上，一个能玩的网页游戏

最近我看到归藏这类 AI 创作者的玩法，最受启发的不是某一个工具，而是整套工作流：

- 先让 Codex / Claude Code 读项目和素材，拆出场景；
- 再用 GPT Image 2 生成视觉分镜；
- 然后把图、交互、视频、网页包装成一个完整的产品展示。

这个思路用在游戏开发上，特别值得拿来说。

不是让 AI 写一个贪吃蛇。

而是让 AI 真的做一个能玩的全栈项目：

- 首页
- 游戏主界面
- 角色设定
- 道具系统
- 关卡规则
- 排行榜
- 移动端适配
- 音效和视觉素材
- 浏览器实测
- Vercel 部署

你可以这样开工：

```
我要做一个网页小游戏，名字叫《夜巡》。
玩法：玩家在一座未来城市里巡逻，用有限电量发现异常事件。
1. 先写 PLAN.md，定义玩法、主循环、胜负条件、关卡、视觉风格；
2. 技术栈用 Next.js + Phaser；
3. 用 GPT Image 2 生成角色、城市背景、道具图标；
4. 用浏览器插件打开本地页面反复测试；
5. 手机端也要可玩；
6. 做完后给我部署说明。
```

OpenAI 官方的 Codex 游戏用例里也强调了这一点：

**不要一上来就说"帮我做个游戏"。**

先让 Codex 写 PLAN.md，把玩家目标、主循环、输入控制、胜负条件、难度曲线、视觉方向、技术栈和里程碑定清楚，再让它实现。

这和人类团队做游戏很像。

区别是——这个小团队，可以只有你和 Codex。

## 案例 6：早上十分钟，邮箱清零

普通白领最烦的不是写代码。

是每天早上打开邮箱，看到几十封未读：

- 老板转发"看一下"
- 客户问合同进度
- 同事抄送的 FYI
- 供应商催确认
- Newsletter 混在中间
- 几封真要今天回

以前你要一封封点开，判断重要性，找上下文，再写回复。

现在可以让 Codex 先做第一遍：

```
@Gmail 帮我看今天的新邮件。
1. 按"必须今天回 / 可以晚点看 / 噪音"分组；
2. 对必须回的，先写回复草稿，不要发送；
3. 缺上下文的，去 @Slack 或 @Google Drive 找资料；
4. 回复语气参考我最近发过的邮件，短一点、自然一点；
5. 最后给我一个 5 分钟处理清单。
```

爽点不是"AI 会写邮件"。

**爽点是它能把邮件背后的上下文串起来。**

客户问"上次方案什么时候发"，它去 Drive 找方案；同事问"那个数据口径定了吗"，它去 Slack 找最后结论；你只需要看草稿、改两句、点发送。

这个案例最容易打动人。因为几乎每个办公室人，都被邮箱和消息流消耗过。

## 案例 7：脏表进，周报出

再说一个所有白领都懂的场景。

领导丢给你一个 Excel。

里面有销售线索、渠道来源、成交金额、客户行业、跟进人、日期。

问题是：

- 表头不统一
- 日期格式混乱
- 有空值
- 有重复客户
- 有些金额带逗号，有些没有
- 同一个渠道写了三种名字

以前你要在 Excel 里一顿 VLOOKUP、筛选、去重、透视表。

现在你可以把表丢给 Codex：

```
帮我分析这个销售线索表。
1. 不要改原始文件，先复制一份工作副本；
2. 清洗日期、金额、渠道和重复客户；
3. 输出本周新增线索、有效线索、成交金额、转化率；
4. 按渠道和销售负责人分别做排名；
5. 生成一页可以发给老板的周报摘要；
6. 标出数据里不确定或需要人工确认的地方。
```

这就是 OpenAI 官方说的"clean and prepare messy data"和"analyze datasets and ship reports"。

它不会让你变成数据分析师。

**它让你从"整理表格的人"，变成"看结论的人"。**

**图16：Excel 数据清洗到周报**

配图建议：一张杂乱 Excel 表格 → Codex 清洗过程 → 右侧输出数据看板：新增线索、成交金额、转化率、渠道排行。

这类场景在销售、运营、市场、人事、财务里都很常见。

它不酷，但它非常值钱。

公司里最浪费时间的，往往就是这些"不难但很碎"的表格活。

## 案例 8：从会议记录到能交的 PPT

白领的另一个噩梦：PPT。

尤其是这种需求：

> "你把今天讨论的内容整理一下，明天上午给老板汇报。"

这句话背后的工作量很大：

- 整理会议纪要
- 提炼结论
- 补数据
- 找配图
- 画流程图
- 做封面
- 调字体
- 对齐
- 检查文字溢出

Codex 现在可以直接处理 `.pptx`。

你可以说：

```
帮我把这份会议纪要做成 8 页汇报 PPT。
1. 受众是老板，重点讲结论和风险，不要写成流水账；
2. 使用现有模板 company-template.pptx；
3. 文字保留为可编辑文本，图表尽量用 PowerPoint 原生图表；
4. 需要配图的页面，用 GPT Image 2 生成统一风格插画；
5. 导出每页 PNG 预览，检查文字溢出、遮挡、字体替换；
6. 最后输出 PPT 文件和一段 1 分钟口播稿。
```

这比"让 ChatGPT 帮我写 PPT 大纲"强太多。

**因为它不是停在大纲——它真的改 deck，真的生成视觉，真的检查版式。**

**图17：会议纪要变 PPT**

配图建议：左侧是一页会议纪要，右侧是 8 页 PPT 缩略图，中间箭头写"提炼结论 / 生成图表 / 检查排版"。

以后做汇报，最重要的能力不是会不会套模板。

**而是你能不能告诉 AI：这份 PPT 到底要说服谁。**

## 案例 9：让群聊自己变成待办

很多公司的低效，不是没人开会。

恰恰是开太多会，但开完没人知道下一步是谁负责。

更真实的情况是：

会议在飞书开，结论发在群里，文件在云文档，负责人在企业微信被 @ 了一下，截止时间藏在某条聊天记录里。

会后聊天经常长这样：

> "这个我来跟一下。"
> "数据口径等财务确认。"
> "下周三前应该能出一版。"
> "谁同步下法务？"

人能听懂，但系统不一定能记录。

Codex 适合做这件事，尤其搭配 Computer Use 和浏览器插件。

如果公司用飞书：

```
打开飞书网页版，进入"增长项目推进群"和今天上午的会议纪要。
输出：
1. 决策结论；
2. 行动项清单：负责人 / 任务 / 截止时间 / 依赖项；
3. 需要追问的问题；
4. 可以直接发到飞书群里的会后总结；
5. 可以创建成飞书待办的任务草稿。

不要直接发送群消息，不要直接创建待办，最后停下来让我确认。
```

如果用企业微信：

```
打开企业微信，看"客户交付项目群"最近 2 天的聊天记录。
帮我整理：
1. 哪些客户需求已经确认；
2. 哪些问题还卡着；
3. 谁负责下一步；
4. 哪些截止时间需要加到日历；
5. 写一版可以发到群里的项目进度同步。

不要直接发送，先让我确认文案。
```

它能把一堆松散的聊天，整理成项目推进表、待办草稿和日历草稿。

这件事特别适合国内白领。

我们每天真正消耗时间的，**不是"大项目战略"，而是飞书、企业微信、腾讯文档、钉钉表格里散落的小碎片**。

**图18：飞书 / 企业微信群聊到行动项**

配图建议：左边是飞书或企业微信群聊截图，中间是 Codex 识别出的"决策 / 待办 / 风险 / 追问"，右边是一张行动项表格：负责人、任务、截止时间、状态。底部显示"待确认后同步到飞书待办 / 企业微信日程"。

这个场景比"AI 写代码"离普通人近得多。

几乎每个团队，都缺一个认真记账的人。

**Codex 可以变成那个永远不嫌麻烦的会议秘书。**

## 案例 10：新人入职包，半天的活，喝杯咖啡的工夫

再举一个非常办公室的场景：新人入职。

一个新同事进来，你要准备：

- 团队介绍
- 项目背景
- 常用链接
- 权限申请清单
- 过去几次会议纪要
- 当前项目状态
- 30 天学习计划
- 谁负责带他
- 第一天要做什么

这些东西公司里其实都有。

只是散在飞书、企业微信、邮件、Google Drive、Notion、腾讯文档、表格里。

Codex 可以把它们捞出来，整理成新人能看的包：

```
帮我为新入职的运营同学准备 onboarding 包。
资料来源：@Google Drive 的团队文档、@Slack 的项目频道、这个文件夹里的会议纪要。
输出：
1. 团队和业务背景；
2. 当前重点项目；
3. 常用链接和权限清单；
4. 前 7 天学习计划；
5. 需要认识的人和他们各自负责什么；
6. 新人第一天的欢迎消息草稿。

不要编造缺失信息，不确定的地方标注"需要负责人确认"。
```

这个案例不炫，但非常实用。

团队里最消耗 senior 时间的事情之一，就是**重复解释背景**。

如果 Codex 能把散落的信息整理成清晰文档，老人少讲很多遍，新人也少迷路。

**图19：新人入职资料包**

配图建议：多个资料源图标（邮件、Slack、Drive、Notion）汇入一份 onboarding 文档，文档里有"7 天计划 / 常用链接 / 关键联系人"。

OpenAI 官方的 Codex 用例里，专门列了"Coordinate new-hire onboarding"。

这说明 Codex 的目标早就不只是工程师。

**它正在进入公司里所有"信息散、流程碎、重复高"的岗位。**

## 我自己每天怎么用 Codex

如果你第一次用，不要一上来就让它"全自动接管工作"。

先从这 5 类任务开始：

**1. 让它读**

```
先不要改任何文件。
帮我读这些资料，告诉我背景、关键结论、待确认问题，以及我下一步应该先处理什么。
```

**2. 让它列方案**

```
这件事先不要做。
给我 3 个处理方案，按耗时、风险、需要谁确认、最终产出比较，并推荐一个。
```

**3. 让它小步执行**

```
先只处理第一步：把这份会议记录整理成行动项表格。
不要创建任务、不要发消息。
整理完先让我确认格式。
```

**4. 让它先 dry run**

```
先模拟执行一遍，列出会修改、移动、归档或发送的内容。
等我确认后再真正执行。
```

**5. 让它写复盘**

```
把这次任务做了什么、用了哪些资料、产出了哪些文件、哪些地方需要人工确认，整理成一份简短报告。
```

这 5 句话，比任何"万能提示词"都重要。

**它们把 AI 从一个会胡乱发挥的聊天对象，变成一个可协作、可监督、可验收的执行者。**

**图20：Codex 五步协作法**

配图建议：读资料 / 列方案 / 小步执行 / dry run / 写复盘，五张卡片排成一行。

## 话也得说回来：三件事得先想清楚

Codex 很强。GPT-5.5 很强。

但它不是魔法。

你给它完全访问权限，它就真的能读文件、改文件、跑命令、访问网络。

这意味着它能帮你，也意味着它能犯大错。

记住这几条：

- **删除、提交、付款、发消息、授权，一律最后人工确认。**
- 第三方一键安装脚本，先让 Codex 审一遍。
- 清理电脑时，先 dry run，不要直接删。
- 批量改文件、归档资料、整理表格时，先让它写计划，再分小步做。
- 重要资料先备份，最好让 Codex 复制工作副本再处理。
- 涉及账号、隐私、密钥，不要随手粘到网页里。
- 让它跑完之后，一定要让它说明验证方法。

AI 时代不是"人不用负责"。

恰恰相反。

**人的责任从"亲手做每一步"，变成"定义目标、设置边界、验收结果"。**

> **能让它跑命令，也要能随时按住它的手。**

**图21：AI 权限安全边界**

配图建议：一个权限开关面板，分成文件、终端、浏览器、账号、删除、提交六项。删除和提交显示"需要人工确认"。

## 结尾：未来不是某天降临，是你今天多说的那一句

我以前判断 AI 工具的标准很简单：它能不能让我更快？

现在标准变了：**它能不能替我跑完一整段工作流？**

装 agent，是一整段工作流。

清理电脑、填申请表、做配图、开发小游戏、整理邮箱、做 Excel 周报、会议纪要变行动项——都是一整段工作流。

这就是 GPT-5.5 + Codex 最让我兴奋的地方。

**它不是让你在聊天框里多得到一个答案。它是让你在电脑上少做很多步骤。**

开头我说，你的电脑里会多一个人。

一周用下来，我更想说的是——

**多的不是一个人，是一种新的"你自己"。**

未来不会哪天突然砸到头上。

它就是从你今天对 Mac 多说的那一句话开始的。
